Unwall Measurement

Does a published page get used by AI, cited, and send people to the creator's post? This design measures each step, compares it to a baseline taken before the page exists, and turns the result into a report the creator can show.

Step 1Is AI using it?Crawlers find the page, and AI tools fetch it to answer a real person's question.Host logs
Step 2Is AI citing it?AI answers list the page or the creator's post as a source, compared with a publish-day baseline.Weekly question checks
Step 3Is it sending people?People arrive from an AI and go on to the creator's post.Referrals and redirect
One-time checkReadableAI can answer from the page text alone. Rerun once on real creator videos.Passed on samples · 15/15

What gets recorded

RecordFields
rundate, engine, question, page, whether the page was cited, whether the post was cited, whether the creator was named, all source URLs
hittime, page, kind (crawler, AI user fetch, AI referral, click to post, other), bot name, IP confirmed or not, referring AI if known
  • Privacy. Visitor IPs are used only to confirm a bot's identity, then dropped. People are counted, not tracked.
  • Comparison videos (next). A few similar videos from the same creators tracked without publishing pages. If those get cited just as often, the pages aren't the cause. Not in the first build.

The test and its bar

  • Size. 3–5 creators, about 5 videos each, 3–5 questions per page, 3 engines, a baseline plus 4 weekly runs. That's roughly 1,500 API calls for the whole test.
  • Pass. At least one page is cited by at least one engine where the baseline showed nothing, and AI tools fetch pages for real user questions.
  • Strong pass. People click through from an AI to the creator's post.
  • Fail. Four weeks of crawls with no fetches and no citations. That's a finding too, and it tells you to change distribution before building more.

Risks and open questions

  • API answers aren't the consumer apps. ChatGPT, Claude and Perplexity in a browser can cite differently from their APIs, so spot-check a few questions by hand each week.
  • Log retention. Railway keeps logs for a limited time that depends on the plan. The daily sync has to run, or that day's data is lost.
  • Spoofed bots. Anyone can claim to be ChatGPT-User. Visits count as confirmed only when the IP matches a range the company publishes; otherwise they're labeled unconfirmed.
  • Referrals are partial. Some AI apps strip the referrer, so referral counts are a floor, not the true number.
  • New domain. A fresh Railway subdomain has no history. A real domain should be in place before publish day.
  • New dependency. Perplexity Sonar needs a new API key. OpenAI and Claude use the keys you already have.

Build order

  1. Host evidence. Access logging, the /go redirect, daily sync, and the classifier. No new keys, and it starts collecting data from day one.
  2. Citation runner. Questions at approval, baseline at publish, weekly runs on OpenAI and Claude, and Perplexity once there's a key.
  3. Results. A results tab per page and a shareable creator report.
  • Each slice ships with a test against local fakes, like Publish live, then one real run before the next slice starts.
